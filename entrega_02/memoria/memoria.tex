\subsection{Rediseño do modelo da práctica anterior}


Despóis da corrección da entrega anterior modificamos o DFM do seguinte xeito:
\begin{itemize}
	\item Baixamos as dimensións de \texttt{Hospedador} e \texttt{Lugar} ó nivel de \texttt{Hospedaxe} para evitar o modelo \emph{Copo de neve}, o cal atopamos vantaxoso por gañar simpleza do modelo e velocidade das consultas (ver \cite{evitarSnowflake}).  
	\item Actualizamos o DFM cos atributos da dimensión \texttt{Eventos} especificados no informe.
	\item Cambiamos as SCD a tipo 2 para conservar os datos do pasado e poder analizalos (dimensións \texttt{Hospedador} e \texttt{Valorador}).	
	\item Cambios sobre o resto de atributos para buscala coherencia co informe anterior.
\end{itemize}

\subsection{Toma de decisións}

Con todo resulta un modelo en estrela. Onde:
\begin{itemize}
	\item A dimensión \texttt{Tempo} está denormalizada, para que en vez de estar representada de forma xerárquica, sea tipo Estrela. Ademáis, como proposto nas teóricas usamos o atributo \texttt{data} como chave primaria (identifica o que ten que identificar).
	\item Á dimensión \texttt{Lugar} tivemos que crearlle unha chave primaria \emph{surrogada} pois pode haber, por exemplo, máis dun barrio \emph{chinés}. Con todo, si forzamos a non duplicidade das ternas \texttt{(barrio, cidade, pais)} con \texttt{UNIQUE KEY}.
	\item A dimensión \texttt{Hospedaxe} ten dos atributos multievaluados (\texttt{Comodidades} e \texttt{Accesibilidade}, que describen prestacións do aloxsmento e formas de chegar a él, respectivamente) e modelarasen con Táboas Ponte.
	\item A dimensión \texttt{Eventos} usa chaves foráneas para asegurar coherencia e restriccións para asegurar que os valores categóricos son os esperados e para evitar duplicados. Ademáis inclúe un índice (\texttt{INDEX}) para que as consultas do tipo: 
		\begin{lstlisting}
SELECT e.evento_id, e.evento_nome, e.impacto
FROM dim_eventos e
JOIN dim_lugar l ON e.lugar_id = l.lugar_id
WHERE e.evento_data = DATE '2024-11-10'
  AND l.cidade = 'Madrid';\end{lstlisting}
sexan veloces, e xustamente son ese tipo de consultas ás que nos interesan (os eventos ocurren nun momento nunha cidade) (ver \cite{index}).
	\item Os atributos \texttt{comodidade} e \texttt{accesibilidade} ó seren multievaluados teñen que ser modelados cunha táboa ponte. Por tanto merecen a súa dimensión propia (ademáis da ponte).
	\item A dimensión \texttt{Chuvia} é dexenerada pois a única métrica que aporta son os mm de precipitacion. Polo tanto ben a podemos incluir na táboa de feitos.
\end{itemize}

\subsection*{Consulta 1: Influe o número de hospedaxes dun hospedador sobre o seu score medio? Canto?}
\addcontentsline{toc}{subsection}{Consulta 1}

\begin{lstlisting}
SELECT 
    h.numero_hospedaxes,
    COUNT(DISTINCT h.hospedador_chave) AS num_hospedadores,
    AVG(v.score) AS score_medio,
    COUNT(v.valoracion_id) AS total_valoraciones,
    -- Ratio de superhosts en este grupo
    SUM(CASE WHEN h.e_superhost = 1 THEN 1 ELSE 0 END) * 100.0 / 
        COUNT(DISTINCT h.hospedador_chave) AS porcentaje_superhosts
FROM feito_valoracion v
JOIN dim_hospedador h ON v.hospedador_chave = h.hospedador_chave
WHERE h.actual = 1
GROUP BY h.numero_hospedaxes
HAVING COUNT(v.valoracion_id) >= 10  -- Filtrar grupos con pocas valoraciones
ORDER BY h.numero_hospedaxes;
\end{lstlisting}

\subsection*{Consulta 2: Cales son os barrios con peores valoracións? Ordeados descendentemente pola valoración media da cidade. }
\addcontentsline{toc}{subsection}{Consulta 2}

\begin{lstlisting}
WITH valoraciones_barrio AS (
    -- Calcular score medio por barrio
    SELECT 
        l.lugar_id,
        l.barrio,
        l.cidade,
        l.pais,
        AVG(v.score) AS score_medio_barrio,
        COUNT(v.valoracion_id) AS num_valoraciones_barrio,
        STDDEV(v.score) AS desviacion_barrio
    FROM feito_valoracion v
    JOIN dim_lugar l ON v.lugar_id = l.lugar_id
    GROUP BY l.lugar_id, l.barrio, l.cidade, l.pais
),
valoraciones_cidade AS (
    -- Calcular score medio por ciudad
    SELECT 
        l.cidade,
        l.pais,
        AVG(v.score) AS score_medio_cidade,
        COUNT(v.valoracion_id) AS num_valoraciones_cidade
    FROM feito_valoracion v
    JOIN dim_lugar l ON v.lugar_id = l.lugar_id
    GROUP BY l.cidade, l.pais
),
ranking_barrios AS (
    -- Combinar y rankear barrios dentro de cada ciudad
    SELECT 
        vb.barrio,
        vb.cidade,
        vb.pais,
        vb.score_medio_barrio,
        vb.num_valoraciones_barrio,
        vc.score_medio_cidade,
        vc.num_valoraciones_cidade,
        -- Diferencia del barrio respecto a la media de su ciudad
        vb.score_medio_barrio - vc.score_medio_cidade AS diferencia_vs_cidade,
        -- Ranking dentro de la ciudad (1 = peor barrio)
        RANK() OVER (PARTITION BY vb.cidade, vb.pais 
                     ORDER BY vb.score_medio_barrio ASC) AS ranking_en_cidade
    FROM valoraciones_barrio vb
    JOIN valoraciones_cidade vc ON vb.cidade = vc.cidade AND vb.pais = vc.pais
    WHERE vb.num_valoraciones_barrio >= 5  -- Filtrar barrios con pocas valoraciones
)
SELECT 
    barrio,
    cidade,
    pais,
    ROUND(score_medio_barrio, 2) AS score_barrio,
    num_valoraciones_barrio,
    ROUND(score_medio_cidade, 2) AS score_cidade,
    ROUND(diferencia_vs_cidade, 2) AS diferencia,
    ranking_en_cidade AS posicion_en_cidade
FROM ranking_barrios
WHERE ranking_en_cidade <= 5  -- Top 5 peores barrios por ciudad
ORDER BY 
    score_medio_cidade DESC,  -- Ciudades con mejor valoración primero
    ranking_en_cidade ASC;    -- Dentro de cada ciudad, peores barrios primero
\end{lstlisting}

\subsection*{Consulta 3: Entre as comodidades e accesibilidades que pode ter un hospedaxe, cal beneficia máis á valoracion ca súa presencia e cal perxudica máis ca súa ausencia?}
\addcontentsline{toc}{subsection}{Consulta 3}

\begin{lstlisting}
-- Top 5 comodidades que MÁS BENEFICIAN (mayor score con ellas)
SELECT * FROM (
    SELECT 
        commodidade,
        'Comodidade' AS tipo,
        ROUND(AVG(v.score), 2) AS score_medio
    FROM feito_valoracion v
    JOIN ponte_hospedaxe_commodidade pc ON v.hospedaxe_id = pc.hospedaxe_id
    GROUP BY commodidade
    HAVING COUNT(*) >= 10
    ORDER BY AVG(v.score) DESC
) WHERE ROWNUM <= 5

UNION ALL

-- Top 5 accesibilidades cuya AUSENCIA más PERJUDICA (menor score sin ellas)
SELECT * FROM (
    SELECT 
        accesibilidade AS commodidade,
        'Accesibilidade (ausente)' AS tipo,
        ROUND(AVG(v.score), 2) AS score_medio_sin_ella
    FROM feito_valoracion v
    WHERE NOT EXISTS (
        SELECT 1 
        FROM ponte_hospedaxe_accesibilidade pa
        WHERE pa.hospedaxe_id = v.hospedaxe_id
    )
    GROUP BY accesibilidade
    HAVING COUNT(*) >= 10
    ORDER BY AVG(v.score) ASC
) WHERE ROWNUM <= 5;
\end{lstlisting}
