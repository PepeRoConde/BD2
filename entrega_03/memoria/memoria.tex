\subsection*{Consulta 1: Obter un índice de centralidade (dentro da cidade) para cada hospedaxe} 
\addcontentsline{toc}{subsection}{Consulta 1}

\emph{Xustificación:} como verase na sección \ref{sec:nulosAA}, imos usar este valor para facer prediccións sobre o precio de cada hospedaxe. Ademáis parecíanos un bo uso das funcións nativas de MongoDB.

Para levar acabo esta consulta precisamos calcular os centroides de cada cidade e logo, para cada hospedaxe calcularemos a distacia ó centroide. O seguinte código crea ditos centroides, agragando os hospedaxes por cidade e facendo a media das súas coordenadas.


\begin{lstlisting}
const centroides = db.listings.aggregate([
  {
    $group: {
      _id: "$city",
      avg_lat: { $avg: "$latitude" },
      avg_lon: { $avg: "$longitude" }
    }
  }
]).toArray();
\end{lstlisting}

Agora que temos eso só nos queda facer un \texttt{updateMany} no que por cada centroide, collemos os hospedaxes desa cidade e calculamos a distacia euclidea do centroide ó hospedaxe. Malia seren moitas liñas, as liñas 8-13 correspóndense co cálculo.

\begin{lstlisting}
centroides.forEach(c => {
  db.listings.updateMany(
    { city: c._id },     // filtro
    [
      {
        $set: {
          centrality: {
            $sqrt: {
              $add: [
                { $pow: [{ $subtract: ["$latitude", c.avg_lat] }, 2] },
                { $pow: [{ $subtract: ["$longitude", c.avg_lon] }, 2] }
              ]
            }
          }
        }
      }
    ]
  );
});
\end{lstlisting}

\emph{Resultados:} Tal cual o fixemos cambia a base de datos, non devolve. Para ver o efecto podemos facer unha mini-consulta de comprobación como \texttt{db.listings.findOne()} e ver que xa figura o novo atributo.

db.listings.aggregate([
  {
    $group: {
      _id: "$host.has_profile_pic",

      max_price: { $max: "$price" },
